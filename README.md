# claimwire

Landing page for agent-identity opt-in. Short, server-rendered, SEO-first.

## Thesis

Short-lived, scoped credentials bound to a workload or agent identity, using
SPIFFE/WIMSE primitives and OAuth token exchange for delegation chains.
Attenuated delegation: a sub-agent only receives permissions its orchestrator
already holds. Every token carries the full on-behalf-of chain, so any
downstream system can answer "which agent did this, acting on whose
authority, with what permissions?". The inversion vs. Descope/ZeroID: the
claim is self-verifying at the resource, not dependent on the hub being
reachable.

## Running locally

```
bun install
bun run dev
```

Then visit <http://localhost:3002>.

## Configuration

Copy `.env.example` to `.env.local` and point it at your backend:

```
NEXT_PUBLIC_API_URL=http://localhost:8000
API_TRUST_SECRET=                 # optional; sent as X-Api-Trust on SSR fetches
```

The waitlist form POSTs to `${NEXT_PUBLIC_API_URL}/claimwire/waitlist`. The CVE
pages fetch from `${NEXT_PUBLIC_API_URL}/cve/{id}` and
`${NEXT_PUBLIC_API_URL}/cve/_sitemap`. Any backend that implements those three
endpoints works; nothing in this repo assumes a specific implementation.

## Hero / spot illustrations

Four images live under `public/img/` and are committed to the repo (Vercel
serves them as static assets, `next/image` handles AVIF/WebP conversion at
request time):

- `hero.png` — the editorial-technical credential composition.
- `step-mint.png`, `step-chain.png`, `step-verify.png` — three how-it-works
  spot illustrations generated by OpenAI `gpt-image-1`.

To regenerate the three spot illustrations (hero stays as-is):

```
OPENAI_API_KEY=sk-... bun run scripts/generate-images.ts
```

The script skips any file that already exists. Delete a target PNG and re-run
to replace it.
